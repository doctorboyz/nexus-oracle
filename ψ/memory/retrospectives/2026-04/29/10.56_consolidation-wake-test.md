## Key Architecture Decisions

1. **Single agent, two roles** — god-port is ONE agent with broky + metty as internal roles, not 3 separate agents
2. **Vault-driven, not daemon** — agent wakes on session, reads vault, acts, writes, sleeps. No main loop.
3. **Shared ψ/ top-level** — inbox/outbox/memory at agent level, role-specific sub-vaults for persistence only
4. **MSG-ACK-RESULT protocol** — PM sends to ψ/inbox/, god-port reads, ACKs, acts, writes result to ψ/outbox/
5. **Repo naming** — renamed god-port-trading → god-port-oracle to match maw convention (critical for `maw wake`)

## AI Diary (150+ words, first-person)

I'm honestly surprised how smoothly the consolidation went. The user had a clear vision — "not a project app, an agent that trades for me" — and that clarity made the architecture decision easy. The shift from "code app" to "agentic AI" paradigm is more than cosmetic; it changes how the system thinks about itself. ## Honest Feedback (100+ words, 3 friction points)

1. **maw naming convention gap**: I created `god-port-trading` as the repo name without checking maw's `{name}-oracle` convention. This caused `maw wake 03-god-port` to fail. I should validate tooling conventions before naming things. The fix (rename to `god-port-oracle`) was simple but the user had to discover the problem first.

2. **Fleet config cleanup was reactive, not proactive**: When I created the new fleet config, I left the old broky/metty entries in place. The fleet showed 5 entries with confused numbering. I should have cleaned up stale fleet entries immediately as part of the consolidation task, not as a separate fix after the user hit an error.

3. **No validation of maw wake after fleet setup**: I wrote fleet configs, updated CLAUDE.md, pushed repos — but never tested `maw wake god-port` until the user tried it. The wake test should have been part of task #5 (update fleet, push, verify), not left for the user to discover.

## Lessons Learned

1. **Validate tooling conventions early** — maw expects `{name}-oracle` on GitHub. When creating repos for maw integration, follow the naming convention from the start.
2. **Clean up stale config immediately** — when consolidating, remove old entries (fleet, references, paths) in the same task, not as a follow-up.
3. **Test the integration path end-to-end** — `maw wake {name}` is the real test. Run it before declaring the task done.
